# ONDO° 온도컴퍼니 — 공식 사이트

**ONDO = ON + DO — "온라인에서 되게 만든다"**

세 가지 서비스(온도 웹 · 온도 클립 · 온도 AI)를 첫 화면에서 한 번에 보여 주고,
각 서비스마다 상세 페이지와 요금·작업물로 연결되는 멀티페이지 정적 사이트입니다.

**세 서비스는 순서가 있는 단계가 아니라 각각 독립된 상품입니다.**
사이트 문구도 그 기준으로 통일해 두었습니다 — "필요한 것만 고르시면 됩니다".
카피를 고치실 때 "웹부터", "그다음", "웹이 있어야" 같은 표현이 들어가지 않게 주의해 주세요.
빌드 도구·프레임워크 없이 순수 HTML/CSS/JS라, 파일을 그대로 올리면 바로 동작합니다.

## 2. GitHub Pages 배포

저장소는 이미 만들어 두셨다고 하셨으니, **이 폴더 안의 내용물 전체**를 저장소 루트에 올리시면 됩니다.
(`ondo-site` 폴더째로 올리면 주소가 한 단계 깊어집니다. 폴더를 열고 **안에 있는 것들**을 올려 주세요.)

### 웹에서 올리는 방법
1. 저장소 페이지 → **Add file → Upload files**
2. 이 폴더 안의 파일·폴더를 전부 끌어다 놓기
3. 아래 **Commit changes** 클릭
4. 저장소 **Settings → Pages** → Source를 **Deploy from a branch**, 브랜치 `main` / 폴더 `/ (root)` → **Save**
5. 1~2분 뒤 `https://<아이디>.github.io/<저장소이름>/` 으로 열립니다

### 명령어로 올리는 방법
```bash
cd ondo-site
git init
git add .
git commit -m "ONDO 사이트 첫 배포"
git branch -M main
git remote add origin https://github.com/<아이디>/<저장소이름>.git
git push -u origin main
```

> `.nojekyll` 파일이 없으면 `assets/` 같은 폴더가 무시될 수 있습니다. 이미 넣어 두었으니 지우지 마세요.

#### 새 작업물 추가하는 순서
1. 사이트 첫 화면을 캡처합니다 (PC 기준, 가로 1400px 이상 권장).
2. **1000 × 512px (약 1.95:1)** 로 맞춰 WebP로 저장 → `images/work/<이름>.webp`
   (다른 비율이면 카드 안에서 위쪽 기준으로 잘려 보입니다. 앱처럼 화면이 좁으면 가운데만 잘라내세요)
3. `_tools/_frag.py`의 `PORTFOLIO`에 한 줄 추가합니다. 인자 순서는
   `(파일이름, 강조색, 주소, 표시할도메인, 이름, 분류, 설명, [태그], 서비스태그, 이미지대체텍스트)`
4. `_tools`에서 생성 스크립트를 다시 돌리면 세 페이지에 한 번에 반영됩니다.

업종별 구조 예시 카드(`work/index.html` 아래쪽)에 데모가 생기면
`<span class="work-soon">데모 준비 중</span>` 을
`<a class="work-link" href="주소" target="_blank" rel="noopener">데모 보기 →</a>` 로 바꾸시면 됩니다.

## 5. 메뉴·푸터를 한 번에 바꾸려면

정적 사이트라 상단 메뉴와 푸터 코드가 7개 파일에 똑같이 들어 있습니다.
하나만 고치면 나머지가 안 바뀌니, **전체 찾아 바꾸기**를 쓰시거나
`_tools/` 안의 생성 스크립트를 고쳐서 다시 만드시면 됩니다.

```bash
cd _tools
for f in _pages.py _p_web.py _p_clip.py _p_ai.py _p_rest.py _p_contact.py; do python3 "$f"; done
```
스크립트는 어디서 실행하든 **사이트 루트에 HTML을 덮어씁니다.**
손으로 고친 내용이 있으면 사라지니, 다시 만들기 전에 백업해 두세요.

## 6. 가격과 상품 스펙 메모

| 서비스 | 사이트 표기 | 무료 수정 |
|---|---|---|
| 온도 웹 | 베이직 5~8만 / 스탠다드 10~15만 / 프리미엄 20만~ | 베이직·스탠다드 1회, 프리미엄 2회 |
| 온도 클립 | 30초 25만→**20만** / 60초 50만→**40만** / 월 관리 100만→**70만**(30초 4편) | **없음** (제작 전 확인으로 대체) |
| 온도 AI | 결과물 8~12만 / ＋전략 15~18만 / ＋강의 25만~ | 2회 |

### 온도 클립 = AI 영상 제작 (영상 편집이 아님)
- 촬영이 없습니다. **알리고 싶은 내용만 받아 AI로 화면과 목소리를 만듭니다.**
- 연출 6종을 제시: 동물 캐릭터 / AI 아나운서 / 실사 느낌 / 일러스트·모션 / 클로즈업 / 전후 대조
- **무료 수정 없음.** AI 영상은 장면 하나를 바꾸려면 전체 재생성이라, "수정 1회 포함"은 사실과 다릅니다.
  대신 **제작 전에 화면 이미지와 대사를 확인받는 절차**를 상품에 넣었습니다 (이 단계에서는 몇 번이든 변경 가능).
- 30초와 60초 금액 차이가 큰 이유(장면 수·재생성 부담)를 요금 섹션과 FAQ에 적어 두었습니다.
- **묶음 할인은 전부 삭제**했습니다.

### 온도 클립 요금표 (오픈 기념 할인 프레임)
| 구성 | 정가 | 할인가 | 할인율 |
|---|---|---|---|
| 숏폼 30초 1편 | 25만원 | **20만원** | 20% |
| 숏폼 60초 1편 | 50만원 | **40만원** | 20% |
| 월 관리 (30초 4편) | 100만원 | **70만원** | 30% |

정가끼리 계산이 맞습니다 — 60초 정가 = 30초 정가 × 2, 월 관리 정가 = 30초 정가 × 4편.
할인가 기준으로도 월 관리 편당 17만 5천원(단건 20만원 대비 12.5% 추가 할인)이라 정기 계약 유인이 성립합니다.

- **60초는 월 관리에 넣지 않습니다** (작업량이 감당되지 않음). 필요하면 건별로 추가한다고 명시해 뒀습니다.
- 60초가 30초의 **정확히 두 배**라, 설명을 "장면 수가 두 배 = 30초 두 편 만드는 작업량"으로 맞췄습니다
  (요금 리드 문구 + FAQ).
- 요금 정책에 **"할인 종료 시 정가로 돌아갑니다"** 를 명시해 뒀습니다. 나중에 값을 올릴 때 근거가 됩니다.

> 실무 메모: 월 관리 편당 17만 5천원이 실질 하한선입니다. 제작 시간이 아직 많이 든다면
> 월 관리를 무리해서 받지 말고 단건 위주로 돌리다가, 손에 익어 제작 시간이 줄었을 때 월 관리를 미는 편이 안전합니다.

### 광고 관련 안전선 (온도 클립)
사이트에 명시해 두었습니다. 광고 문제는 고객에게 돌아가므로 그대로 지켜 주세요.
- 실존 인물·연예인의 얼굴·목소리를 만들지 않습니다.
- 실제로 없는 메뉴·시설·자격·수상 이력을 있는 것처럼 만들지 않습니다.
- 화면이 실제 매장 모습이 아니면 **AI로 만든 영상임을 밝히시도록 권고**합니다.
  (표기 의무는 상황에 따라 다르므로 단정하지 않고 "안전합니다" 정도로 씀)

### "가장 많이 선택" 배지 → "추천 구성"
판매 실적이 없는 상태에서 "가장 많이 선택"은 지어낸 사회적 증거입니다. 전부 **"추천 구성"** 으로 바꿨습니다.

### 온도컴퍼니 자기 사이트의 문의폼도 제거
백엔드가 없어 실제로 전송되지 않았습니다. **카카오톡 한 곳으로 모았습니다.**
살리려면 `contact/index.html` 의 주석 처리된 폼을 풀고 Formspree 주소를 넣으면 바로 동작합니다.

### 세금계산서·현금영수증 문구 전부 삭제
사업자등록 전이라 발행할 수 없으므로 FAQ와 요금 정책에서 관련 문구를 아예 뺐습니다.
결제 방법(크몽 / 계좌 이체)만 남겼습니다. 나중에 사업자등록을 하시면 그때 항목을 추가하면 됩니다.

### 문구에서 걷어낸 것 — "AI 티"
손님이 알 필요 없는 **내부 사정과 자기 변명**을 사이트에서 뺐습니다.
- "문의폼을 두지 않았습니다 · 외부 서비스 · 월 건수 제한 · 조용히 사라집니다" 안내 박스 → 삭제
- "솔직하게 적습니다", "없는 실적을 지어내지 않겠습니다",
  "확실하지 않은 것을 확실하다고 말씀드리지 않겠습니다", "저희가 책임지는 건 ~",
  "서로 곤란해집니다" → 전부 삭제하거나 사실 서술로 교체
- 판단 근거를 길게 붙이던 문장은 손님이 알아야 할 결론만 남기고 잘랐습니다

**앞으로 문구를 추가하실 때 기준:** "이 문장이 손님의 결정에 도움이 되는가."
도움이 안 되고 우리 쪽 사정 설명이면 빼는 게 맞습니다.

점검 환경에 **Chromium만** 설치되어 있어 Safari·Firefox 실기 테스트는 못 했습니다.

## 8. 사이트에서 지킨 원칙

- 없는 실적·리뷰·고객사를 만들지 않았습니다. 실제로 배포된 세 사이트만 캡처와 함께 걸었고,
